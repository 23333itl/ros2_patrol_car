本记录对应 `lidar_noise_stddev`、三组共享基线 profile、分运动类别修正统计与晋级检查的实现。默认保持 `simulation_stable`，未增加 RViz 平滑，未调整底盘、EKF、Nav2 或探索状态机。已有未提交修改保留。

## 修改及原因

- launch 在启动节点前拒绝负数和非有限噪声，并将有效值传到 xacro 的激光 `<stddev>`。日志同时输出 profile、噪声、扫描匹配开关和分辨率，记录器额外查询实际 `robot_description`，避免只验证参数文本。
- YAML 锚点使三个对照与当前默认使用同一基线；关闭匹配对照只改变开关，两个候选只改变指定先验。旧 `odometry_only` 未改动，因为它的分辨率和触发阈值不同，不能混入本轮单变量对照。
- 修正按同一时刻的机器人位置比较。新增静止、直行、转弯、回访统计与仿真时间归一化累计量；晋级使用运动期间 P95，避免静止时间稀释指标。没有观测的类别不冒充零误差。
- 录制与回放串行运行，隔离 ROS domain 和 Gazebo 分区。回放过滤旧 `map -> odom`；真值只用于评价。
- 异常窗口保存实际激光距离、静态 TF、位姿、时间、速度及原录制 TF 上下文。候选修正另存 `map_to_odom.csv`，事件元数据明确区分两者来源。

首次三倍速基线有 30 条消息过滤丢弃日志（主要从约 404.4 仿真秒开始），结果明确为 `incomplete`，未用于晋级。停止本任务的加速批次，保留 `replay_noise_0p01/` 失败记录。第二次启动检测到本任务中断后残留的 SLAM，生命周期失败，保留 `replay_v2_noise_0p01/`、`replay_v2_noise_0/`，均不参加验收。已清理参数路径属于本任务的残留，补齐软退出超时后的强制回收及测试。正式第三批先确认 ROS domain 189 为空，使用两倍速，结果目录为 `replay_v3_noise_0p01/` 与 `replay_v3_noise_0/`。

回放另外提前 0.2 仿真秒供应录制中的里程计 TF，原时间戳和值保持不变，不合成或外推 TF。这避免单格激光队列等待原 EKF 到达时序时，在加速回放中被后续扫描挤掉；四组策略相同，实际供应策略写入 `playback`。它只影响离线回放，不修改在线 SLAM 的 TF 时间戳、发布周期或超时。

每个噪声档位过滤一次，基线和三个对照共享同一输入摘要。回放保存实际节点参数、最终地图、连续墙面拟合、修正指标与首次异常窗口。输入缺帧、消息过滤丢弃、缺少里程计括点或缺少配对激光不算通过；若仍出现丢帧，须进一步降低倍率重跑。
